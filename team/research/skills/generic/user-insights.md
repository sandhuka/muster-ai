# User Insights Skill

Understand who the target user is, what problems they have, and how they currently solve them.

## Jobs-to-be-Done

For each target segment, define:

- **When** [situation] **I want to** [job] **so I can** [outcome]
- Layer: functional (get the task done), emotional (feel accomplished), social (belong/impress)
- Prioritize by: high importance + low satisfaction with current solutions = biggest opportunity

## Personas

Build 2-3 personas max. Each needs:

- Segment label, demographics, experience level with your product's domain
- Goals (why they want this product)
- Frustrations (what's broken with current solutions)
- Current behavior (what they do today — free tools? Competitor apps? Manual process? Nothing?)
- Trigger (what would make them try something new)

Define likely segments based on your product's domain and validate or revise with data.

## Pain Point Mapping

Categorize pains: functional (can't accomplish the core task efficiently), financial (premium tools too expensive), process (too many steps to get started), guidance (don't know how to get the best results). Rate by severity × frequency.

## User Journey

Map: Awareness → Consideration → Activation (first completed core experience) → Retention (regular habit) → Referral. For each stage: what the user does, drop-off risks, opportunities to improve.

The critical moment is activation — the first time a user completes the core experience and feels it was personalized for them.

## Output Format
Document findings in `knowledge-base/research/user-insights.md` using the standard research doc structure:
- **Current State**: 5-10 line summary
- **Findings**: Personas, JTBD, pain points, journey maps
- **Open Questions**: What needs further investigation
- **History**: Dated one-liner entries for major updates
