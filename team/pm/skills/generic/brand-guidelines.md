# Brand Guidelines Skill

## Purpose
`knowledge-base/brand-guidelines.md` defines the product's identity for all agents. Content uses it for voice and tone, UI/UX uses it for visual direction, Marketing uses it for positioning. Inconsistency here creates a fragmented user experience. This file is the single source of brand truth.

## Structure Template

### 1. Brand Identity
- **Name**: Full name, pronunciation guide, origin/meaning
- **Tagline**: Primary tagline and any approved variants
- **Mission statement**: One sentence — what the product exists to do
- **Brand promise**: What users can always expect from the experience

### 2. Brand Personality & Voice
- **Personality traits**: 3-5 adjectives that define the brand character (e.g., "knowledgeable but approachable," "encouraging but not cheerleader-y")
- **Tone spectrum**: Where the brand falls on key axes:
  - Formal ←→ Casual
  - Serious ←→ Playful
  - Technical ←→ Simple
  - Authoritative ←→ Friendly
- **Voice do's and don'ts**: Specific examples of on-brand vs. off-brand phrasing
- **Example phrases**: 5-10 sample sentences showing the voice in action (onboarding, notifications, encouragement, error states)

### 3. Messaging Hierarchy
- **Primary message**: The one thing users should understand about the product (ties to core value prop)
- **Supporting messages**: 3-4 secondary messages that reinforce the primary (e.g., science-backed, multi-discipline, adapts to your life)
- **Elevator pitch variants**: 1-sentence, 2-sentence, and paragraph-length descriptions
- **Positioning statement**: For [target user], [Product Name] is the [category] that [key differentiator], unlike [alternatives] which [limitation]

### 4. Visual Direction
- **Color palette direction**: Primary, secondary, accent color families and the mood they convey (specific hex codes are UI/UX agent's job)
- **Typography preferences**: Serif vs. sans-serif, weight preferences, readability priorities
- **Character persona descriptions**: Brief personality and visual description for each character — enough for the content and design teams to maintain consistency
- **Aesthetic keywords**: 3-5 words capturing the visual feel (e.g., "minimalist premium," "clean and confident," "warm but sophisticated")
- **Photography/imagery style**: If applicable, direction for any non-character visual assets

### 5. Naming Conventions
- How to refer to the app's features (e.g., "routine" not "workout plan," "exercise" not "move")
- How to refer to app sections (e.g., "Today," "Library," "Progress")
- Character name usage rules (when to use names vs. generic references)
- Capitalization rules for product-specific terms

### 6. Competitive Positioning Statement
- How the product talks about itself relative to competitors (without naming them directly in user-facing content)
- Key differentiators to emphasize
- What the product is NOT (anti-positioning to maintain focus)

## Writing Principles
- **Voice should be consistent across all surfaces**: in-app copy, App Store listing, marketing emails, push notifications, error messages. One brand, one voice.
- **Brand personality should reflect the product philosophy**: science-backed but approachable, smart but not intimidating, personal but not intrusive.
- **Keep visual direction high-level**: Brand guidelines set the direction; UI/UX agent details the implementation. Don't specify exact hex codes, font sizes, or pixel dimensions here.
- **Test with edge cases**: The voice should work in celebration ("Great week!"), encouragement ("Ready to get back?"), and error states ("We couldn't load your routine"). If it doesn't work in all three, it's not the right voice.
- **Reference research for persona alignment**: Brand voice should resonate with the primary persona (Efficient Professional). Check against `knowledge-base/research/user-insights.md`.
