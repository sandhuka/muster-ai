# App Store Listing & ASO

## Purpose
Define the methodology for writing and optimizing App Store listing content. This is the single highest-leverage content surface for an iOS-only product — the listing is the storefront. See `team/content/skills/seo-guidelines.md` for web SEO. See `team/content/skills/brand-voice.md` for voice consistency. See `team/legal/skills/app-store-review.md` for Apple metadata compliance requirements.

## App Store Metadata Structure

### Title (30 characters max)
- Format: `Brand Name - Primary Keyword`
- Primary keyword should describe the core value, not a feature
- Example: "[Product Name] - Smart Daily Workouts"
- Never: all-caps words, emoji, competitor names

### Subtitle (30 characters max)
- Expand on the title with a secondary value proposition
- Include a keyword not already in the title
- Example: "Strength, Yoga & Stretching"
- Rotate subtitles with each update to test keyword performance

### Keywords Field (100 characters max)
- Comma-separated, no spaces after commas
- Do not duplicate words already in title or subtitle (Apple indexes those automatically)
- Mix high-volume and long-tail terms
- Include misspellings of key terms if space allows
- Refresh keywords with each release based on App Store Connect impression/conversion data

### Fitness Category Keyword Strategy

| Priority | Keyword Cluster | Rationale |
|----------|----------------|-----------|
| High | daily workout, personalized routine, smart fitness | Core value proposition — what makes the product different |
| High | strength training, yoga app, stretching | Discipline coverage — captures category browsers |
| Medium | home workout, no equipment, bodyweight | Equipment-free positioning — traveling persona |
| Medium | workout planner, fitness schedule, weekly plan | Planning intelligence — differentiator vs. video libraries |
| Low | exercise app, fitness tracker, health | High volume but extremely competitive — unlikely to rank initially |

## Description Structure

The App Store description has two zones: **above the fold** (first 3 lines visible without tapping "more") and **below the fold** (full description).

### Above the Fold (First 170 Characters)
This is the only copy most users will read. Must contain:
1. What the app does (one sentence)
2. Key differentiator
3. Health disclaimer sentence (Apple compliance — see `team/legal/skills/app-store-review.md`)

### Full Description Structure
1. **Hook** (1-2 sentences): Problem statement in user's language
2. **Solution** (1-2 sentences): How the product solves it
3. **Key features** (bulleted list, 4-6 items): Lead with benefits, not feature names
4. **How it works** (3 steps): Simple flow — open → see routine → do it
5. **Free vs. Premium** (short comparison): What's free, what premium unlocks
6. **Subscription terms** (required by Apple): Price, renewal, cancellation instructions
7. **Disclaimer**: Health/fitness disclaimer

### Feature Bullet Writing
- Lead with the benefit, then the feature: "Know what to do today — smart daily routine generation based on your goals and recovery"
- Not: "Smart Algorithm: Uses 10 constraint rules to generate personalized routines"
- Keep each bullet to one line (under 80 characters ideally)
- Use consistent grammatical structure across all bullets

## Screenshot Copy

### Principles
- Each screenshot tells one story — one benefit, one visual, one headline
- Headlines: 5-7 words max, benefit-first, uses brand voice
- Subheadlines (optional): One supporting detail, 8-12 words
- First 3 screenshots are critical — most users don't scroll further

### Screenshot Sequence (Recommended)
| Position | Focus | Headline Pattern |
|----------|-------|-----------------|
| 1 | Today screen with routine | "Your routine. Ready when you are." |
| 2 | Algorithm rationale / "why" | "Every session has a reason." |
| 3 | Multi-discipline coverage | "Strength. Yoga. Stretching. One plan." |
| 4 | Weekly plan view | "Your week, designed around recovery." |
| 5 | Exercise animation quality | "150+ exercises. 3D animated guides." |
| 6 | Progress tracking | "See your consistency build." |

## "What's New" Release Notes

### Format
- Lead with the most user-visible change
- 2-4 bullet points max — users don't read long changelogs
- Use plain language, not technical descriptions
- End with a forward-looking note if appropriate

### Patterns
- Feature addition: "New: [what it does for you]. [One detail.]"
- Improvement: "[Thing] is now [better how]. [Specific change.]"
- Bug fix: "Fixed an issue where [user-visible problem]."
- Never: "Various bug fixes and improvements" (wastes the opportunity)

## Review Response Templates

### Positive Review (4-5 stars)
- Thank specifically for what they mentioned
- Reinforce the value they found
- Keep it brief (2-3 sentences)
- Pattern: "Thanks for the feedback on [specific thing]. [Reinforcement]. [Forward note if relevant.]"

### Constructive Review (2-3 stars)
- Acknowledge the specific issue
- Explain what you're doing about it (or why it works that way)
- Invite them to reach out for support
- Never defensive, never dismissive
- Pattern: "Appreciate you sharing this. [Acknowledgment]. [Action/explanation]. Reach out to [support email] if you'd like to discuss."

### Negative Review (1 star)
- Empathize with frustration
- Address the specific complaint if possible
- Offer direct support channel
- Pattern: "Sorry this didn't meet your expectations. [Specific response]. We'd like to help — reach out at [support email]."

### Review Response Rules
- Respond within 48 hours of posting
- Never argue, never be sarcastic
- Never reveal upcoming features as promises ("we're adding X soon") — only confirm shipped features
- Maintain Intelligent Coach tone — calm, direct, helpful

## Optimization Cadence
- **Every release**: Update keywords, refresh "What's New," review description for accuracy
- **Monthly**: Check keyword rankings in App Store Connect, compare impression/conversion rates, A/B test subtitle if supported
- **Quarterly**: Full description rewrite based on performance data, refresh screenshot copy

## Principles

1. **Above the fold is everything**: Most users decide from the title, subtitle, icon, and first screenshot. Invest disproportionate effort in these elements.
2. **Benefits over features**: "Know what to do today" beats "10-rule constraint algorithm." Users care about what the app does for them, not how it works internally.
3. **Subscription terms are content, not fine print**: Apple requires them, but they're also a trust signal. Be transparent about pricing and cancellation — it reduces refund rates and improves conversion.
